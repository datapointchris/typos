# CHANGELOG


## v1.0.0 (2026-08-11)

### Bug Fixes

- **ci**: Run ruff and pytest without depending on repo dev deps
  ([`25bc37c`](https://github.com/datapointchris/typos/commit/25bc37c2de1f0e336e845b859975a9549d972f0e))

`uv run ruff` resolved ruff from the repo's own dependencies, so a repo that treats ruff as a fleet
  tool rather than a project dependency failed to spawn the binary instead of linting. ruff now runs
  through uvx at the version its pre-commit hook pins; pytest is supplied with --with so a real test
  suite is never silently skipped; and mypy's guard tests for the dependency by import, since the
  [tool.mypy] section it used to look for is now in every repo.

Regenerated by `forge dies run maintenance/sync-ci.sh`.

- **nvim**: Create the data dir on first write
  ([`fb28a15`](https://github.com/datapointchris/typos/commit/fb28a15693a914fa6ce103b7b89847092a61726c))

setup() called mkdir on the sessions directory, so merely loading the plugin built ~/shart/typing on
  machines that sync nothing and would never capture a keystroke. Capture is scoped to notes_root,
  so a machine without one writes nothing — the plugin has to touch no filesystem to stay a no-op
  there, which is what lets consumers drop their guards and load it as a plain remote spec.

The directory now appears with the first captured event, guarded by a flag so it costs one mkdir per
  session rather than one per keystroke.

### Features

- Scaffold capture plugin and CLI shell
  ([`3cebaa7`](https://github.com/datapointchris/typos/commit/3cebaa75e3f64f2d26da39998a38d33c6c296acd))

Two-layer architecture: Lua plugin captures keystrokes via vim.on_key() when the buffer path is
  under notes_root, writing append-only JSONL to the configured data dir (default
  ~/shart/typing/sessions/). Python CLI reads that log for analysis.

- lua/typos/init.lua — capture, :TyposToggle, :TyposStatus -
  src/typos/{config,storage,main,analyzer} — Python package skeleton - tests/test_storage.py — JSONL
  append/iter coverage - pyproject.toml — uv_build, ruff, mypy, semantic_release config -
  .pre-commit-config.yaml — full hook suite mirrored from ~/tools/relate

Analysis layer (damage scoring, correction-event reconstruction, report output) intentionally
  stubbed. Event schema and report shape documented in .planning/design.md; next steps in
  .planning/status.md.

- **analyzer**: Reconstruct, bigrams, damage scoring
  ([`8b6a8f6`](https://github.com/datapointchris/typos/commit/8b6a8f625367d814ca91bf54cf25e75063cb018c))

Phase-1 analysis from the captured event stream:

- reconstruct(events) walks insert-mode events in ts_ns order, builds the virtual buffer, and emits
  Correction tuples on backspace bursts (wrong = reversed deletion order, right = subsequent
  retype). - bigram_stats(char_timings) aggregates per-bigram counts and inter-keystroke intervals
  from the reconstructed buffer. - damage_scores(stats) computes Amphetype-style weights: count *
  max(0, median_iki - user_baseline) / median_iki. Baseline is the median IKI across all bigrams in
  the analysis window (your own rhythm, not a global one).

CLI wiring: - typos report shows totals (sessions, chars, bigrams, corrections) and the top-N
  damaging bigrams in a Rich table. - typos problems shows top corrections grouped by (wrong,
  right). - Whitespace bigrams render with visible markers (space, return, tab) so they are not
  invisible in tables.

Captured along the way: vim's keytrans() leaks K_SPECIAL escape bytes for some terminal-only key
  codes, producing non-UTF-8 in the JSONL. Sanitize at write (lua sanitize_key encodes 0x80-0xFF as
  <bin:HEX>) and tolerate at read (storage uses errors='replace' and skips bad JSON lines), so
  historical logs remain analyzable.

10 new analyzer tests including a fixture-based smoke test against a real captured session
  (tests/fixtures/sample-session.jsonl).

- **ci**: Add the standard validation workflow

- **nvim**: Make dirs the auto-on list, on/off an override
  ([`e352645`](https://github.com/datapointchris/typos/commit/e35264522c985ccc20d7e63318f80a21e2f9262c))

notes_root was one directory doing two jobs: naming where prose lives, and deciding whether capture
  ran at all. Those come apart now. `dirs` is a list of directories capture switches on inside, and
  :TyposOn / :TyposOff are a session override on top of it — each idempotent, so a keybind asserts a
  state rather than reading the current one first, and :TyposAuto returns to following the list.

:TyposToggle is gone. The state is three-way, and a flip across three states has no single obvious
  meaning.

The override is not persisted, for the reason it never was: a remembered "off" is how weeks of
  capture disappear unnoticed, so the worst case stays the session you turned off in.

The buffer path is still read per keystroke rather than tracked by a BufEnter autocmd. "Am I writing
  prose" is a property of the current buffer, so asking it directly cannot fall out of step with
  splits, tabs, terminals, or a file moved mid-session, and it costs one prefix comparison.

Verified headless: auto-on inside dirs, silence outside, both override directions, the return to
  auto, a bare string accepted for a single dir, and setup() still creating no directories.

- **report**: Date filtering and days active
  ([`82ba2bc`](https://github.com/datapointchris/typos/commit/82ba2bc99cfba5d04b56e0176c9d29131d9c3ec4))

storage gains parse_session_date plus since/until kwargs on list_session_files, iter_all_events, and
  a new days_active count. analyzer.parse_since handles 'Nd' relative or YYYY-MM-DD absolute.

report and problems commands gain --since (default 7d). Report header reads "typos report — last 7d"
  and shows days active alongside session count.

- **report**: Iki variance with week-over-week delta
  ([`3e07895`](https://github.com/datapointchris/typos/commit/3e07895f69fd2c5e8fec406c4c35072ea7ba4ff7))

Population variance of typing-burst IKIs across sessions in a window, rendered in ms². Compares
  current 7d vs prior 7d (14d→7d ago) and annotates direction ("down from Xms² last week" or "up
  from").

char_timing_burst_ikis is the shared primitive — both compute_wpm and compute_iki_variance derive
  from it.

- **report**: Longitudinal damage deltas (improved/worsened)
  ([`c878878`](https://github.com/datapointchris/typos/commit/c878878c51cc45510c42c26e2f0287499e39cb30))

damage_deltas(prior_scores, current_scores, threshold=0.2) returns (improved, worsened) lists of
  DamageDelta entries. A bigram is improved when its current damage dropped >threshold relative to
  prior, worsened when it rose by the same. Bigrams missing from either window are skipped.

Report compares current 7d vs prior 7d (the 14d→7d ago window) and adds two sections: "recently
  improved" and "recently worsened", each showing prior → current scores in damage-magnitude order.

Tests use synthetic DamageScore fixtures rather than walking real events through reconstruction —
  the damage formula's user-baseline interaction makes constructing precise damage profiles via
  events brittle, while DamageScore is the actual contract damage_deltas operates on.

- **report**: Mistyped words aggregation
  ([`5b54c52`](https://github.com/datapointchris/typos/commit/5b54c52da39f0928ad426b30e39bb89f7b2ed0ae))

Correction now records word_context — the trailing non-whitespace run in the buffer at flush time.
  mistyped_words(text, corrections) aggregates by that context, computing typed/corrections/rate.

The reconstruction loop now flushes a pending correction *before* appending a whitespace boundary
  char, so word_context reads the word that was just being corrected rather than empty space.
  Without this, a pending correction would leak across word boundaries until the next backspace
  burst, attributing fixes to the wrong word.

Report gains a "top N mistyped words" table after the bigrams. problems command shows the word view
  by default; --raw falls back to the previous (wrong, right) pair view.

- **report**: Wpm rolling 7d and 30d
  ([`6984662`](https://github.com/datapointchris/typos/commit/6984662e0b8cecb4a0b62efe13bbaabdd626c052))

Burst-based WPM: chars / 5 over the sum of inter-keystroke intervals < BURST_THRESHOLD_NS (5s). Idle
  gaps drop out so the metric reflects active typing speed, not calendar time.

ts_ns from vim.uv.hrtime() resets per boot, so IKIs are only meaningful within a single session
  file. compute_wpm takes Iterable[Iterable[dict]] and lets the caller group events per session;
  main.py's per_session_events helper materializes one session at a time so file handles close
  cleanly.

WPM 7d and 30d are independent of the report's --since window — fixed metric axes per design.md.

### Refactoring

- Stop shipping one user's directories as defaults
  ([`41b0fdf`](https://github.com/datapointchris/typos/commit/41b0fdfc50042c64fc3256baeaa6a621c864e88b))

The plugin knew where prose lived (~/notes) and where to write (~/shart/ typing), on both the Lua
  and Python sides. Those are facts about one person's machines, not about typing, and a plugin that
  ships them is configuring its author rather than its user.

dirs becomes watch_dirs and defaults to empty: capture watches nowhere until a config says where. An
  unconfigured install is inert rather than guessing, and :TyposStatus says so instead of looking
  broken.

The session path falls back to $XDG_STATE_HOME/typos, then ~/.local/state/ typos, resolved
  identically in lua/typos/init.lua and src/typos/config.py — the two halves have to agree without
  either knowing the other's machine. Sessions are state by the usual test: they survive runs,
  nobody authored them, and losing one changes what the analyzer reports rather than costing a
  recompute. TYPOS_DATA_DIR still overrides both, which is how a synced location gets chosen from
  outside.

Drops notes_root, DEFAULT_NOTES_ROOT and TYPOS_NOTES_ROOT from config.py: nothing imported them, and
  the concept now lives entirely in watch_dirs on the capture side.

Verified headless that both halves resolve the same path for TYPOS_DATA_DIR, for XDG_STATE_HOME, and
  for neither, and that an empty watch_dirs captures nowhere and creates nothing.

### Testing

- **nvim**: Cover the capture rule
  ([`b712884`](https://github.com/datapointchris/typos/commit/b71288471d40b6e204624aa14d6c34d08f6cf041))

The capture layer had no automated coverage at all — stylua checked its formatting and nothing
  checked its behaviour. Two rewrites landed on it this week (the watch_dirs auto-on rule, then
  dropping the shipped defaults) with only manual checks behind them, and `task test` ran pytest
  alone, which is the exact half-the-repo blindness this Taskfile's header warns about.

tests/capture_spec.lua drives real nvim rather than adding busted or plenary: the whole surface is
  vim.on_key, a buffer path and a file write, so driving nvim tests the thing itself and adds no
  dependency to a repo whose other half is Python. It covers auto-on inside watch_dirs, silence
  outside, both override directions, the return to auto, a bare string where a list is expected, the
  recorded bufpath the analyzer groups by, and an unconfigured install writing nothing.

Verified it fails when it should: inverting the watch_dirs check made it report "a buffer outside
  watch_dirs captures nothing" and exit non-zero.

Wires it into `task test` alongside pytest, and into pre-commit under the existing custom test
  block, gated on types: [lua] to match how pytest is gated on Python.
